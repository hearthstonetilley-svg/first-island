# Astra audit 15 (GPT-6-Astra), 19 Oct 2026: v0.9.0, the day cycle (PR #29)

Brief: adversarial review of the day cycle against the owner-approved startup and performance contract. Run visibly in tmux session island, window audit, with codex exec, read-only.

## Verdict, verbatim

ready to leave draft: no

1. **[P2] Shadows snap across the island at dusk and dawn.** [src/render/scene.ts:654](src/render/scene.ts) flips the directional light’s horizontal direction by 180° at `height = -0.05`. Its intensity simultaneously jumps from `0.16` to `0.45`, with an abrupt warm-to-blue colour change. At that boundary the moon is still effectively invisible. This produces a lighting and shadow discontinuity twice per cycle; the four sampled phases miss it.

2. **[P2] A nighttime storm brightens the ocean instead of darkening it.** [src/render/scene.ts:646](src/render/scene.ts) blends water toward a fixed grey multiplied by `1.6`, independent of night depth. At midnight, this increases the tint’s linear luminance **7.35×**. The ocean is unlit, so the reduced light intensity does not compensate. Storm onset therefore abruptly brightens nighttime water. Scale the storm tint by the current nighttime illumination.

3. **[P2] The shader-rebuild check can pass despite recompilation.** [src/render/scene.ts:670](src/render/scene.ts) returns the current pipeline-cache size, not the number of pipelines built. Three.js releases an unused previous pipeline when compiling its replacement, so the cache can retain exactly the same size. Consequently, [scripts/eval-sandbox.mjs:306](scripts/eval-sandbox.mjs) can pass while shaders rebuild throughout the cycle. Count actual shader/pipeline creation calls monotonically.

Validation: client and server typechecks passed; boundary and tint calculations reproduced directly. Browser visual checks and the full eval were not run. No files changed.

## What was done
