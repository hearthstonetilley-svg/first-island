Brief 2.2: survive a lost WebGPU device.
- Cause: the loss happens browser-side in headless Chromium's software WebGPU (reproduced on a bare page with no
  JavaScript destroy call), so it is not our code. On real hardware it can happen after driver resets, sleep or
  memory pressure.
- Fix: on device loss, during start-up or later, the scene is rebuilt on a fresh WebGL2 renderer from the same world
  data without reloading, with a short notice; the label and FPS counter are cleared so they never claim a renderer
  that is not drawing.
