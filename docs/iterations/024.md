# Iteration 024: first-load instrumentation and baseline

Scope: [Brief 2.1](../briefs/BRIEF-2.1-first-load-fps.md). This iteration measures the existing render path before changing it.

- Keep `?debug=1` diagnostics in the app: first 600 RAF intervals, CPU submission time, time to first animation submission, phase costs, scene resource counts, and a final spike/stability summary. Read `window.__ISLAND_DEBUG__` or the `[island-debug]` console messages. Time to first frame is a submission timestamp, not a compositor presentation measurement.
- Add `?post=0` to bypass both AO and bloom. Correct the FPS counter's first-frame initialization.
- Add `scripts/profile-load.mjs`, using the installed headless Chromium and DevTools protocol, fresh browser profiles, real time, fixed 1280×800/DPR 1. It refuses to overwrite captures. `--frames` allows shorter diagnostic captures; the default is 600. No dependencies or browser installs.

## Measurements

This environment exposes no GPU device. All captures use software WebGL2 (SwiftShader); these timings cannot establish the owner's native WebGPU or real GPU FPS.

The first attempt reached over 500 frames but exceeded the profiler's polling limit before saving. It consistently showed roughly 700 ms cadence after startup. The saved, paired comparisons below use 60 frames each; their raw reports correctly retain `complete: false`. The permanent app recorder still collects 600 frames. The profiler's limit has been extended for slow software runs.

| Cold software WebGL2, seed 1 | Full post | `post=0` |
| --- | ---: | ---: |
| Time to first animation submission | 1,750 ms | 1,335 ms |
| Initial render CPU submission | 1,127 ms | 721 ms |
| Median of 59 measured RAF intervals | 683.3 ms | 416.7 ms |
| Worst interval | 4,166.5 ms | 3,116.5 ms |
| Intervals over 50 ms | 58 | 58 |
| Median CPU submission after frame 10 | 2.4 ms | 1.7 ms |

Post off reduces the measured median by about 39%. Both runs use a 2048² shadow map, DPR 1, 66,564 terrain vertices, 50,625 ocean vertices, 299 trees in 18 instanced meshes, and about 410,240 structural triangles. These are resource counts, not GPU timings or proof that shadows/geometry are free.

Raw reports: [full post](024-profile-seed-1.json), [post off](024-post0-profile-seed-1.json).

The initial render costs hundreds of milliseconds even without post-processing. Later CPU submissions are short while RAF cadence remains slow: there is both first-use work and sustained raster/post cost. The fix must address both. Tree instancing is already in use; arbitrary geometry reductions are not justified by these measurements.

## Validation and screenshot check

`npm run build` and `npm test` pass (23 tests). The screenshot batch includes seeds 1, 42 and 2026 plus forced WebGL2 for seed 1, and the paired post-off capture. Short secondary profiles are image checks, not FPS benchmarks.

Inspected all five saved images together. All show complete islands, resolved backend/FPS labels, visible shoreline foam and animated water. Seeds 42 and 2026 retain the dark rock channels and varied broadleaf crowns; default and forced WebGL2 seed 1 match in layout and lighting. The post-off image loses subtle contact shading/bloom but retains the scene. The extremely low software FPS is visible in the HUD; the short four-frame captures have an unsettled smoothing counter and are not performance evidence. No blank canvas or shader error is visible. These pictures do not verify real-hardware smoothness.

The warm-up and adaptive-quality fixes follow in the next iteration. Nothing was pushed.
