# Iteration 025: precompile, hidden warm-up and adaptive quality

Scope: [Brief 2.1](../briefs/BRIEF-2.1-first-load-fps.md), following the [measured baseline](024.md).

## Changes

- Keep the canvas hidden and the loading label visible while precompiling the scene. Direct rendering uses `renderer.compileAsync(scene, camera)`; post rendering uses `PassNode.compileAsync(renderer)`, which calls the same renderer API against the configured MRT target.
- Warm the complete post-processing graph by rendering it while hidden. Three.js 0.180's `PostProcessing` has no public `compileAsync`; these renders also cover shadow pipelines, bloom's internal passes, GTAO, output conversion and initial allocations. Await `renderer.waitForGPU()` after each hidden draw, including the final high-quality draw. Start the visible wave/tree animation clock at zero.
- Prewarm the AO-free graph as well. Low quality bypasses GTAO; bloom and the scene pass remain. Shared scene/bloom nodes avoid duplicating those computations within a frame.
- Bound asynchronous compilation/fences to 30 seconds. A timeout shows an error; late completion skips further draws and releases the renderer. Existing renderer initialization deadlines/fallback canvases remain in place.
- Measure visible RAF intervals in two-second windows after warm-up. A median above 25 ms reduces pixel ratio first (`1.5 → 1`, `1 → 0.75`); a subsequent slow window disables AO. Show `high`, `balanced` or `low` beside FPS. Never oscillate back up. Reset sampling on tab visibility changes and resize; skip rendering in hidden tabs.
- Keep all debug diagnostics and `post=0`. Record quality changes, their measured window medians and the current render configuration. The first 600 rendered animation frames are retained; hidden warm-up frames are excluded. Time to first frame means animation submission after warm-up, not compositor presentation. The stability summary is an estimate using trailing 30-frame windows, not a smoothness guarantee.
- Add debug-only controls for isolated comparisons: `?debug=1&quality=high` holds full quality, `&pixelRatio=0.75` changes render resolution, and `&shadow=1024` compares the shadow map. Normal loads keep 2048² shadows, accepted geometry and tree placement.

## Reproduce

Run the dev server, then use the installed Chromium profiler, for example:

```sh
node scripts/profile-load.mjs --step NNN
node scripts/profile-load.mjs --step NNN --case post0 --post 0 --quality high --frames 60
node scripts/profile-load.mjs --step NNN --case webgl2 --renderer webgl2 --frames 30
```

Every command writes a tracked PNG and JSON report under `docs/iterations/`; inspect its image and commit that iteration immediately. Use unique step/case names. `--chrome` selects an already installed Chromium. The default sample count is 600; short image/comparison runs explicitly retain `complete: false`. Periodic JSON checkpoints preserve partial data if a very slow profile is interrupted. The tool uses real RAF time, not virtual-time FPS. It explicitly selects SwiftShader, so its timings describe software rendering only.

On real hardware, open `/?debug=1` and `/?debug=1&post=0` separately. Read `[island-debug]` console messages or `window.__ISLAND_DEBUG__`; the report includes the actual backend, initial/current pixel ratio, shadows, mesh/instance/vertex counts, phase costs, individual frames, quality changes and the 600-frame summary. Use `&quality=high` for a fixed-quality comparison. Real GPU/native WebGPU evidence remains external to this environment.

Quality transitions:
- At 2067 ms: balanced, render DPR 0.75, AO on; preceding window median 675.0 ms.
- At 5200 ms: low, render DPR 0.75, AO off; preceding window median 475.0 ms.

- Warm-up changes *when* cold work happens: the loading label remains for about 5.3 seconds in the fixed-high software run instead of showing the island around 1.75 seconds and then hitching. The saved baseline worst interval was 4,166.5 ms; fixed-high after warm-up was 883.3 ms, and the full adaptive run's worst was 699.9 ms. The fixed-high median remains similar (650 versus 683.3 ms), so precompilation is not presented as a steady-state FPS improvement.
- At fixed quality, post off measures 400 ms versus 650 ms with full post, about 38% less. DPR 0.75 measures 575 ms, about 12% less in this single run. Shadow 1024² measures 649.9 ms versus 650 ms at 2048²: no meaningful improvement here. Keep the accepted shadow quality rather than reduce it without evidence.
- The adaptive run reaches DPR 0.75, then AO off with bloom retained. Its final 120-frame median is 450 ms, about 31% below the fixed-high run. Software rendering remains very slow: 597 of 599 measured intervals exceed 50 ms. These results verify removal of the measured cold hitch and operation of fallback; they do **not** establish smooth real-hardware rendering.
- Resource checks retain 66,564 terrain vertices, 50,625 ocean vertices and 18 instanced tree meshes. Seeds 1 / 42 / 2026 contain 299 / 331 / 421 trees and roughly 410k / 445k / 443k structural triangles. World generation and scene construction take tens to low hundreds of milliseconds, rather than accounting for the multi-second queued first-use hitch. These counts do not isolate geometry GPU cost; no speculative terrain or vegetation reduction was made.
- Native WebGPU and real GPU frame times remain unverified because this environment exposes no GPU device. The retained diagnostics and comparison controls are the handoff for checking the owner's original hardware report.

## Verification and screenshot findings

`npm run build` passes with the existing bundle-size advisory. All 32 tests pass, covering the 600-frame recorder, visibility discontinuity, quality thresholds/order/reset, bounded compilation/fences, late cleanup, renderer fallback and deterministic worlds.

Inspected all eight PNGs together and compared them with the iteration 024 images. Every capture shows a complete island, ocean, sky, resolved backend and readable quality/FPS labels. No blank output, missing post texture or obvious shader failure is visible. The seven comparison/multi-seed profiles that collect console errors report none; the earlier full 600-frame run did not collect that metadata.

- [High, seed 1](025-high-seed-1.png): keeps the accepted dark rock, green slopes, varied crowns, foam and narrow reflection path. Geometry/layout match the baseline; water phase differs.
- [Adaptive, seed 1](025-seed-1.png), [seed 42](025-seed-42.png), [seed 2026](025-seed-2026.png) and [forced WebGL2](025-webgl2-seed-1.png): all reach `low` and retain complete coastlines, rock crevices, mixed canopy silhouettes and animated water. Lower DPR visibly softens tree outlines, rock detail and distant ripples; thin shoreline foam has more aliasing. This is the explicit quality/performance tradeoff, not an unchanged-fidelity claim.
- [DPR 0.75, AO on](025-pixels075-seed-1.png): visible softness is consistent with the resolution change, with the full scene and high-quality post graph retained.
- [1024² shadows](025-shadow1024-seed-1.png): remains visually close at this camera distance, but offers no measured cadence benefit. The normal default stays 2048².
- [Post off](025-post0-seed-1.png): contact shading/bloom are subtler or absent, while the ocean, terrain, trees, lighting and labels remain intact.

The screenshots confirm correct output through the quality transitions. Static images cannot prove smooth animation, and their low software FPS is not evidence of real GPU performance. Native WebGPU/owner hardware confirmation is still required.
