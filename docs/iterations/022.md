# Iteration 022: REVIEW-4 startup blocker

Scope: REVIEW-4 point 1 only. Points 2–4 (rock shading, sun glitter and canopy shapes) are unchanged.

## Change

- Both preferred and forced-WebGL2 initialization have a four-second deadline.
- A preferred timeout, rejected promise or constructor error starts a fresh renderer with `forceWebGL: true`.
- Each attempt owns a separate canvas. The successful canvas replaces the placeholder; a timed-out attempt stays detached and is disposed if it eventually finishes. A late rejection is handled without affecting the active renderer.
- If the final attempt times out or fails, the label gives a clear WebGL2 error and reload/graphics-acceleration advice, and the FPS label reads `renderer unavailable`.
- The small pure startup decision function has explicit ready/timeout/error tests for automatic selection and explicit WebGL2. Async tests cover the deadline boundary, fresh fallback, timer cleanup, late success/rejection, both attempts hanging, explicit-WebGL2 failure and constructor failure.

## Checks

- `npm run build`: passes; unchanged Three.js bundle-size advisory.
- `npm test`: 20 passing tests (13 startup tests and 7 existing world tests).
- All 12 normal loads pass: seeds 1, 42, 7 and 99, three runs each. No WebGPU browser-feature disabling flags were used.
- Explicit WebGL2 passes; disabling all 3D APIs shows the intended error instead of leaving the startup label stuck.
- All 14 saved images were opened and inspected as one screenshot batch before this commit. The 13 success images show the complete island scene, a resolved WebGL2 label and the FPS HUD. No capture is blank or stuck on `starting renderer`. The failure image clearly shows `WebGL2 initialization failed. Enable graphics acceleration and reload.` and `renderer unavailable`.
- The existing accepted visuals remain present. Pale peaks, broad sun glitter and the current broadleaf shapes were deliberately left unchanged per scope.
- This environment selected software WebGL2. Native WebGPU and hardware frame-rate performance are not claimed by this startup check.

## Reproduce

```sh
python3 scripts/check-startup.py --step <unused-three-digit-step>
```

The script runs seeds 1, 42, 7 and 99 three times each with normal renderer selection and the original headless Chrome/SwiftShader flags. It does not disable WebGPU features for those 12 loads. It also checks explicit `?renderer=webgl2` and one `--disable-3d-apis` load for the failure message. It refuses to overwrite an earlier iteration. Its JSON report records final DOM labels, URLs, image paths, file sizes and wall-clock command durations; durations include software rendering and are not application startup benchmarks.
